## What this is
Inoa Games is a browser game hub owned by **Inoa Services** (Eduardo Inoa, Methuen, MA). One link, no download, works on phones (touch), laptops (keyboard) and gamepads. Friendly for kids, deep enough for adults. Every game shares one **hero profile** (XP, coins, hero level) stored in `localStorage['inoa.profile']` through the engine's `results()`; the hub front page shows it.

It is a **static site**: `index.html` (hub) + `games/*.html` (one page per game) + `engine/` + `packs/` (asset bundles) + `thumbs/` (tile screenshots). No build step is needed to deploy. Three.js r170 loads from jsDelivr via an import map in each page.

## How to work
```bash
npm install                      # three (for tests), playwright, gltf-transform
npm start                        # serve locally at http://localhost:5173
node test/run.js drift test/drift.js      # headless test of one game (screenshots in test/out/)
npm run test:all                 # every game (landscape; add W=390 H=844 for portrait)
node test/run.js junk test/engine.js      # engine contract
SW=1 node test/run.js index test/pwa.js   # offline / service worker
node tools/build_packs.mjs       # after changing any packs/<game>.json
npm run test:party               # multiplayer: local PeerServer + host/phone/guest pages
python3 tools/build_hub.py       # after changing hub-src/ or adding a game/thumb
```
- Software rendering in headless Chromium is slow: tests call `window.__GAME.update(1/60)` in loops instead of waiting in real time. Keep `window.__READY` and `window.__GAME` hooks working in every game.
- **Look at screenshots** after every visual change (and at 390×844 portrait: `W=390 H=844 node test/run.js ...`).
- jsDelivr may be blocked in the cloud sandbox; the harness routes three.js to node_modules so tests still run.
- Hero: the hub stores `profile.hero = {model, color}`; games read it with `E.hero()` (Drift, Runner, Tide Lines default to it).

## Multiplayer
Hub **Party** section and every title screen open a room (QR + 4-letter code). Phones join at `pad.html`. Online friends use the link in the party panel. Read `docs/MULTIPLAYER.md` before touching `engine/net.js`; keep `npm run test:party` green.

## Non-negotiable rules
1. Static + client-side only (no server needed). Scripts only from jsDelivr (import map); fonts from Google Fonts.
2. All assets CC0/original. **No real brands, franchises or real people** (a fan game of a famous franchise got shut down within 2 days in Sept 2026).
3. Friendly by default (forgiving, no harsh fail states in kids' games), optional hard modes for adults. All ages: no stranger chat.
4. Every round ends with `E.results(...)` so XP/coins reach the shared profile.
5. Touch + keyboard + gamepad in every game. Key instructions read aloud with `E.say()`. EN/ES where text matters.
6. Lighting gentle (bloom ≤ .2 by day), 60 fps target on a 2021 mid-range phone, auto quality drop exists in the engine.
7. Don't break `engine/inoa3d.js` API used by 10+ games; extend it additively and re-run `npm run test:all`.

## Deploy
Vercel serves the repo root as a static site (`vercel.json`: `cleanUrls` off so the service worker never caches redirects; immutable cache on `packs/assets/`; `.vercelignore` keeps source assets/tools/tests out). **As of 2026-10-15 no Vercel project exists for this repo** on the owner's team — it must be imported (vercel.com → Add New → Project → this repo) so every push to `main` deploys automatically. With the Vercel CLI: `npx vercel --prod` from the repo root.
